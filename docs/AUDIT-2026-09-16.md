## 8. Architecture notes for the next milestone

- **Realtime.** Keep `httpOnly` cookies (they are why an XSS cannot steal a
  session). To use Supabase Realtime in the browser, add a server function
  that returns the current `access_token` (short-lived, refreshed by the
  server) and call `supabase.realtime.setAuth(token)` on the memoised browser
  client. Then subscribe to `postgres_changes` on `direct_messages`,
  `chat_messages`, `notifications`.
- **Per-branch capacity.** Capacity is per *venue* but Mulliri/Moncherie/Sophie
  each have 18 branches. `venue_locations.capacity` should exist and
  `book_venue()` should count per location when one is given. The migration
  adds the nullable column; enforcement is a follow-up once real numbers exist.
- **i18n.** `react-i18next` with `sq` as default and `en` fallback; extract
  strings route by route. `<html lang>` should follow the active locale.
- **Payments.** `donations.provider_ref`/`method='card'` exist; wire a
  provider webhook (Stripe or a local PSP) into a server route that flips
  `pending → confirmed` — remove the manual admin confirmation once live.
- **Tests.** Add pgTAP RLS tests ("user B cannot update user A's profile")
  and Vitest component tests for the booking form and slot picker.
